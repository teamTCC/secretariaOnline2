## Fase TX — Padrão Outbox (10.1a)

Toda ação de negócio que gera notificação chama `OutboxEventPublisher.enqueue(...)` **na mesma transação** da mutação. Use cases **não** injetam `OutboxEventJpaRepository`.

```kotlin
@Transactional
fun execute(command: ForgotPasswordCommand) {
    val token = tokenService.issueOneTimeToken(...)
    outboxPublisher.enqueue(
        eventType = OutboxEventTypes.PASSWORD_RESET_REQUESTED,
        aggregateType = "Usuario",
        aggregateId = usuario.id,
        payload = mapOf("email" to usuario.email.value, "nome" to usuario.nome, "token" to token),
    )
}
```

## Fase Dispatch — OutboxDispatcher (10.1b)

```kotlin
@Scheduled(fixedDelay = 5000)
@Transactional
fun dispatch() {
    val pending = outboxRepo.findPendingEvents(now, PageRequest.of(0, 50))
    pending.forEach { event ->
        val handler = handlers.first { it.supports(event.eventType) }
        handler.handle(...)
        event.status = "PROCESSED"
        outboxRepo.save(event)
        notificationLogRepo.save(NotificationLogEntity(...))  // canal EMAIL, status SENT
    }
}
```

Depois do handler, o dispatcher grava `notification_log`. `RequestTransitionOutboxHandler` e `ComunicacaoOpsOutboxHandler` usam [`TemplateEngine`](../../backend/modules/comunicacao/src/main/kotlin/br/ufpr/sept/so2/modules/comunicacao/application/TemplateEngine.kt) (`{{variavel}}` no catálogo V015) e [`InAppNotificationService`](../../backend/modules/comunicacao/src/main/kotlin/br/ufpr/sept/so2/modules/comunicacao/application/InAppNotificationService.kt) (`communication_delivery` IN_APP). Fallback HTML se o código não existir no catálogo.

- `SELECT` com lock pessimista + `SKIP LOCKED` (`jakarta.persistence.lock.timeout = -2`)
- Falha: permanece `PENDING`, `attempt_count++`, backoff 30s → 5min → 1h
- Após 8 tentativas: `DEAD` (não entra mais na fila)

## 10.1c — Destinatário abre `?ott=` e troca por sessão

`RequestTransitionOutboxHandler` inclui no e-mail um deep-link `/solicitacoes/{id}?ott=<jwt>` (audience `request:{uuid}`, JTI único). O cliente **não** autentica com senha nesse link:

```
POST /auth/ott  { "token": "<jwt>" }
  → ExchangeOttUseCase
  → 200 + cookies (mesmo contrato de POST /auth/login)
```

Replay do mesmo token → **401**. Detalhe: [T-F0-001](../F0 — Público/T-F0-001-LOGIN.md) F0.1-g/h. SMTP catcher **não** está no `ops/docker-compose.yml` — leia o JWT no payload de `outbox_event`.
