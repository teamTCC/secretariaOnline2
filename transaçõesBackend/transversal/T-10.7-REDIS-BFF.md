# T-10.7 — Cache Redis no BFF (Dashboard)

> **Diagrama de referência:** [`foundationDocs/sequenceDiagrams/F1 — Aluno/US-F1-001-DASHBOARD.md`](../../foundationDocs/sequenceDiagrams/F1 — Aluno/US-F1-001-DASHBOARD.md)  
> **Status:** ✅ Redis cache-aside nos 4 dashboards BFF com TTL 60s

---

## Por que o Cache foi Adicionado

O diagrama do dashboard (CA-05) especifica que o BFF deve consultar o Redis antes de ir ao Postgres:

- **SLA FCP < 1,5s**: cada endpoint `/bff/dashboard/*` faz 4–6 queries ao Postgres. Com cache, a resposta típica cai de ~150ms para ~5ms.
- **Reduzir carga na demo**: múltiplos usuários abrindo `/inicio` simultaneamente geram pico de queries idênticas. Cache de 60s absorve a rajada.
- **Degradação controlada**: quando `_degraded = true` (algum bloco falhou), o resultado **não é cacheado** — o próximo request tenta Postgres de novo.

## CacheConfig.kt — RedisCacheManager

```kotlin
// app/config/CacheConfig.kt
@Configuration
@EnableCaching
@ConditionalOnProperty(name = ["CACHE_TYPE"], havingValue = "redis")
class CacheConfig(private val redisConnectionFactory: RedisConnectionFactory) {

    @Bean
    fun cacheManager(): RedisCacheManager {
        val config = RedisCacheConfiguration.defaultCacheConfig()
            .entryTtl(Duration.ofSeconds(60))
            .serializeValuesWith(
                RedisSerializationContext.SerializationPair.fromSerializer(
                    GenericJackson2JsonRedisSerializer()
                )
            )
        return RedisCacheManager.builder(redisConnectionFactory)
            .cacheDefaults(config)
            .build()
    }
}
```

O cache só é ativado quando `CACHE_TYPE=redis`. Sem essa variável, o `CacheManager` padrão do Spring (no-op) é usado — sem Redis, sem erro.

## Cache-Aside Manual nos Controllers

O cache-aside é implementado manualmente (não via `@Cacheable`) para permitir lógica condicional: **resultados degradados não são armazenados**.

```kotlin
// DashboardAlunoController.kt (padrão aplicado nos 4 endpoints)
@GetMapping("/aluno")
@PreAuthorize("hasAuthority('dashboard.view')")
fun dashboardAluno(authentication: Authentication): ResponseEntity<Map<String, Any?>> {
    val userId = authentication.userId()
    val cacheKey = "aluno:$userId"

    // 1. Tenta o cache primeiro
    cacheManager.getCache("bff-dashboard")?.get(cacheKey, Map::class.java)?.let {
        @Suppress("UNCHECKED_CAST")
        return ResponseEntity.ok(it as Map<String, Any?>)
    }

    // 2. Monta o dashboard (com graceful degradation)
    val result = buildAlunosDashboard(userId)

    // 3. Só cacheia se não houve degradação
    if (result["_degraded"] != true) {
        cacheManager.getCache("bff-dashboard")?.put(cacheKey, result)
    }

    return ResponseEntity.ok(result)
}
```

> A chave da secretaria não usa UUID pois o dashboard agrega dados de todo o sistema (não é por usuário).

## Comportamento com `_degraded = true`

Quando qualquer bloco do dashboard falha (ex.: `solicitacoes` timeout), o resultado inclui `"_degraded": true`:

```json
{
  "kpis": { "horasFormativas": { "atual": 80 } },
  "pendencias": null,
  "eventos": [...],
  "_degraded": true
}
```

**Este resultado NÃO é armazenado no cache.** O próximo request vai direto ao Postgres, dando ao bloco problemático uma nova chance de responder. Isso evita propagar um estado degradado por 60 segundos.

## Como Ativar em Dev / Produção

### Variáveis de ambiente

```bash
CACHE_TYPE=redis          # ativa RedisCacheManager (sem isso: no-op cache)
REDIS_HOST=localhost      # host do Redis (padrão: localhost)
REDIS_PORT=6379           # porta (padrão: 6379)
```

### application.yml

```yaml
spring:
  data:
    redis:
      host: ${REDIS_HOST:localhost}
      port: ${REDIS_PORT:6379}
```

---

## Redis no docker-compose

```yaml
# ops/docker-compose.yml (trecho)
redis:
  image: redis:7-alpine
  container_name: so2-redis
  ports:
    - "6379:6379"
  restart: unless-stopped
  healthcheck:
    test: ["CMD", "redis-cli", "ping"]
    interval: 10s
    timeout: 5s
    retries: 3
```

Para usar localmente sem Docker, basta instalar Redis 7 na máquina e definir `CACHE_TYPE=redis`.

## Invalidação de Cache

O cache atual **não invalida proativamente** — usa expiração por TTL (60s). Isso é intencional para a demo do TCC:

- **Consistência eventual aceitável:** dashboards com dados de até 60s atrás são ok para o contexto acadêmico.
- **Se precisar invalidar imediatamente** (ex.: após o aluno submeter solicitação), adicione:

```kotlin
cacheManager.getCache("bff-dashboard")?.evict("aluno:$userId")
```
