# T-10.1 — Outbox (observar o efeito das transações)

> **Transação:** [`T-10.1`](../../transaçõesBackend/transversal/T-10.1-OUTBOX.md)  
> **Diagrama:** [`10.1-outbox-notificacao.md`](../../foundationDocs/sequenceDiagrams/transversal/10.1-outbox-notificacao.md)

Não existe `POST /outbox` de negócio. Você **dispara** um use case e **observa** a linha. Admin: [T-10.6](T-10.6-admin-outbox.md).

Dispatcher: `@Scheduled` ~5 s. Status: `PENDING` → `PROCESSED` | retry backoff → `DEAD` (8 tentativas).

Mailhog: [http://localhost:8025](http://localhost:8025)

---

## Passo 1 — Gerar um evento conhecido

Faça [T-F0-002](../F0-publico/T-F0-002-recuperar-senha.md) (`iam.password_reset_requested`) **ou** abra uma solicitação (`solicitacoes.aberta`).

---

## Passo 2 — SQL

```sql
SELECT id, event_type, status, attempts, last_error, created_at
FROM outbox_event
ORDER BY created_at DESC
LIMIT 20;
```

Copie `id` → `{{outboxId}}`.

---

## Passo 3 — API admin

```
GET {{baseUrl}}/admin/outbox?page=0&size=20
GET {{baseUrl}}/admin/outbox?status=PENDING
Authorization: Bearer {{accessTokenAdmin}}
```

**Esperado 200** paginado. Detalhe:

```
GET {{baseUrl}}/admin/outbox/{{outboxId}}
```

Payload completo (token de reset, e-mail, etc.). **Não** commite prints com JWT de 1 uso.

Em ~5 s `PENDING` vira `PROCESSED` se Mailhog/SMTP estiver up. SMTP down: permanece `PENDING` e `attempts` sobe.

Tipos úteis para grep: `iam.password_reset_requested`, `iam.usuario_criado`, `solicitacoes.aberta`, `contato.recebido`, `certificate.issued`, `exports.ready`, `atendimentos.created`.
