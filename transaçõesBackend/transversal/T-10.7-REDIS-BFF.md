# T-10.7 — Redis: Cache BFF + Policiamento de Logout

> **Status:** ✅ Redis 7-alpine — cache BFF (TTL 60 s) + revogação de access tokens (logout forçado)

---

## Por que Redis foi adicionado

Dois papéis distintos, um único container:

### 1. Cache BFF Dashboard (CA-05)

O diagrama do dashboard especifica que o BFF deve consultar o Redis antes de ir ao Postgres:

- **SLA FCP < 1,5s**: cada endpoint `/bff/dashboard/*` faz 4–6 queries ao Postgres. Com cache, a resposta típica cai de ~150ms para ~5ms.
- **Reduzir carga na demo**: múltiplos usuários abrindo `/inicio` simultaneamente geram pico de queries idênticas. Cache de 60s absorve a rajada.
- **Degradação controlada**: quando `_degraded = true`, o resultado **não é cacheado** — o próximo request tenta Postgres de novo.

### 2. Policiamento de Logout / Revogação de Token (Dual Cookie)

Com a migração para dual cookie HttpOnly (access_token + refresh_token), o Redis assume o controlo do ciclo de vida dos access tokens:

- **Logout individual**: o JTI do access token é gravado no Redis com TTL = tempo restante do token.
- **Logout forçado (detecção de roubo)**: quando um refresh token já utilizado é reenviado, o Redis grava um marcador `auth:force-logout:user:<uuid>` que invalida **todos** os access tokens emitidos antes desse momento.

## Esquema de chaves Redis

| Prefixo | Conteúdo | TTL | Responsável |
|---------|----------|-----|-------------|
| `bff-dashboard` (Spring cache) | Dados do dashboard serializado | 60 s | `@Cacheable` / cache-aside |
| `auth:revoked:jti:<jti>` | `"1"` | Tempo restante do access token | `AuthController.logout()` |
| `auth:force-logout:user:<uuid>` | Epoch-ms do evento | `accessTokenTTL` (15 min) | `RefreshTokenUseCase` (reuse detection) |

## Revogação — Dois Mecanismos

### JTI Blacklist (logout voluntário)

```kotlin
// AuthController.logout()
tokenRevocationPort.revokeAccessToken(jti, expiresAt)
// → Redis: SET auth:revoked:jti:<jti> "1" EX <ttl_restante>
```

### Force-Logout por Usuário (roubo de token detectado)

```kotlin
// RefreshTokenUseCase — quando isUsed() ou isRevoked():
tokenRevocationPort.forceLogoutUser(
    userId = stored.usuarioId,
    ttl = Duration.ofSeconds(jwtTokenService.accessTtlSeconds),
)
// → Redis: SET auth:force-logout:user:<uuid> <epoch-ms-atual> EX 900
```

### Verificação no filtro JWT

```kotlin
// JwtAuthenticationFilter.doFilterInternal()
if (jti != null && tokenRevocationPort.isRevoked(jti)) → reject 401

if (issuedAt != null && tokenRevocationPort.isUserForcedLogout(userId, issuedAt)) → reject 401
```

O filtro tem **política fail-open**: se o Redis estiver indisponível, um aviso é logado e o token é aceite (evita derrubar a aplicação por falha de Redis).

## CacheConfig.kt — RedisCacheManager (BFF)

```kotlin
@Configuration
@ConditionalOnProperty(name = ["spring.cache.type"], havingValue = "redis")
class CacheConfig {
    @Bean
    fun redisCacheManager(connectionFactory: RedisConnectionFactory): RedisCacheManager {
        val config = RedisCacheConfiguration.defaultCacheConfig()
            .entryTtl(Duration.ofSeconds(60))
            .disableCachingNullValues()
            .serializeKeysWith(...)
            .serializeValuesWith(GenericJackson2JsonRedisSerializer())
        return RedisCacheManager.builder(connectionFactory)
            .cacheDefaults(config)
            .build()
    }
}
```

O cache só é ativado quando `CACHE_TYPE=redis`. Sem a variável, o `CacheManager` padrão do Spring (in-memory) é usado.

## Cache-Aside BFF (degradação controlada)

```kotlin
// DashboardAlunoController.kt
val cacheKey = "aluno:$userId"
cacheManager.getCache("bff-dashboard")?.get(cacheKey, Map::class.java)?.let {
    return ResponseEntity.ok(it)
}
val result = buildAlunosDashboard(userId)
// NÃO cacheia resultado degradado
if (result["_degraded"] != true) {
    cacheManager.getCache("bff-dashboard")?.put(cacheKey, result)
}
```

**Resultado com `_degraded: true` não é armazenado.**

## Como Ativar em Dev / Produção

### Variáveis de ambiente

```bash
CACHE_TYPE=redis          # ativa RedisCacheManager (sem isso: in-memory)
REDIS_HOST=localhost      # ou "redis" dentro do Docker Compose
REDIS_PORT=6379
```

### Docker Compose (stack completa)

```bash
# Sobe Postgres + Redis + Backend (backend container)
docker compose -f ops/docker-compose.yml up --build

# Sobe apenas infra (dev com Gradle bootRun local)
docker compose -f ops/docker-compose.yml up postgres redis
```

## Invalidação de Cache BFF

O cache atual usa expiração por TTL (60s). Para invalidar proativamente (ex: após o aluno submeter solicitação):

```kotlin
cacheManager.getCache("bff-dashboard")?.evict("aluno:$userId")
```
